# DocLight ✦ 轻量可视化文档站

简洁优雅、现代感的自托管文档站：**浏览器里直接所见即所得排版**，深浅色主题自动跟随系统。

![TypeScript](https://img.shields.io/badge/TypeScript-ES2022-3178C6) ![node](https://img.shields.io/badge/node-%E2%89%A522.13-339933)

## 启动

```bash
npm install               # 安装依赖（运行时：smol-toml、marked、turndown、turndown-plugin-gfm、dompurify、yaml）
npm start                 # 构建并自动探测空闲端口（默认从 4173 起）
PORT=8080 npm start       # 临时指定起始端口（环境变量覆盖配置文件）
```

构建分三步：服务端 `tsc`（`tsconfig.server.json`）、前端 `tsc` 类型检查 + **esbuild 打包**（`tsconfig.client.json` + `scripts/build-client.mjs`）、测试 `tsc`（`tsconfig.tests.json`）。前端由 esbuild 打包成单文件 `public/app.js`（IIFE，浏览器 `es2022`，非 ES 模块）——`app.ts` 依赖 `dompurify` 与共享的 `src/markdown.ts`，后者又引入 `marked`、`turndown` 与 `turndown-plugin-gfm`（GFM 表格、删除线等规则），`tsc` 单独输出会留下浏览器无法解析的裸 `import`。

启动后按提示访问，例如 `http://localhost:4173`。

### 配置文件（TOML）

正式配置写在 TOML 文件里：默认读取 `<项目根>/doclight.toml`，也可用 `DOCLIGHT_CONFIG`
指向别处。**首次启动会自动在默认路径生成一份全注释的模板**——所有键都以 `#` 给出、
即全部沿用内置默认值，按需取消注释即可生效（模板本身不改变任何行为）。已经存在同名
文件时绝不覆盖，本地修改可安心保留。若**文件存在却解析失败**，启动会报错退出并指出行号，
不会静默忽略。未设置的键直接省略：

```toml
port = 4173
host = "127.0.0.1"          # 省略表示监听全部网卡
strictPort = false          # true 时端口占用直接报错，不再向后探测
basePath = "/editor"        # 可选：站点挂载在子目录时设置
dataDir = "/var/lib/doclight"

icp = "浙ICP备12345678号-1"
police = "京公网安备11010502030123号"
copyright = "© 2026 Mooling"
# icpUrl / policeUrl 未配置时按内置规则推导，无需写出
```

### 配置优先级

```
内置默认值  <  doclight.toml  <  环境变量
```

配置文件是正式载体，环境变量只作**临时覆盖**：且仅覆盖它显式设置的那些键，其余键仍读文件。
**变量存在即视为设置**——`DOCLIGHT_ICP=""` 会清空备案号而**不**回退到文件，方便临时关闭悬挂。
路径由 `DOCLIGHT_CONFIG` 指定（它只定位文件，不参与值的覆盖）。

### 环境变量（覆盖配置文件）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DOCLIGHT_CONFIG` | `<项目根>/doclight.toml` | 配置文件路径 |
| `PORT` | `4173` | 起始端口；被占用时自动向后探测 |
| `DOCLIGHT_HOST` | 全部网卡 | 监听地址，如 `127.0.0.1` |
| `DOCLIGHT_DATA_DIR` | `<项目根>/data` | 数据目录（`pages/*.md`、`spaces.json`、`auth.json`） |
| `DOCLIGHT_BASE_PATH` | 未设置（自动识别） | 公开挂载路径，如 `/editor`；空串或 `/` 强制根路径 |
| `DOCLIGHT_DEV_MODE` | 未设置（关闭） | 仅开发时启用，允许登录后编辑内置页面的源码 |
| `DOCLIGHT_STRICT_PORT` | 未设置 | 非空即启用；端口占用直接报错，不再向后探测 |
| `DOCLIGHT_ICP` | 未设置 | 网站备案号，如 `浙ICP备12345678号-1` |
| `DOCLIGHT_ICP_URL` | 工信部备案系统 | 覆盖备案号链接 |
| `DOCLIGHT_POLICE` | 未设置 | 公安联网备案号，如 `京公网安备11010502030123号` |
| `DOCLIGHT_POLICE_URL` | 按备案号推导的查询页 | 覆盖公安备案号链接 |
| `DOCLIGHT_COPYRIGHT` | 未设置 | 版权行，如 `© 2026 Mooling` |

> 类型以 TOML 为准：`strictPort` 只认布尔 `true`，端口必须是 `1–65535` 的整数，
> 否则启动时报错退出——**不会**静默退回默认值。环境变量是字符串，`DOCLIGHT_STRICT_PORT`
> 沿用「非空即启用」的旧语义（空串视为关闭）。

> 作为 systemd 服务运行时建议在 TOML 里固定 `port` 并设 `strictPort = true`：
> 反向代理只指向一个固定端口，静默漂移会导致代理落空。

### 子目录部署

DocLight 会尝试从代理保留的请求路径识别挂载前缀；例如访问 `/editor` 或 `/editor/` 时可识别为子目录部署。自动识别对未知的单段路径采用启发式判断；如果路径与空间或页面名称冲突、无法识别深层路径，或代理剥离了前缀，应显式配置 `basePath = "/editor"`，或启动时设置 `DOCLIGHT_BASE_PATH=/editor`。显式配置优先；设置空串或 `/` 可强制根路径部署并禁用自动识别。公开地址、静态资源、API 和登录 Cookie 使用有效前缀，不信任客户端声明的代理前缀。前缀不是访问控制机制，代理应限制后端访问并独立实施所需访问控制。修改配置后需重启 DocLight。

### 内置文档开发模式

默认情况下内置空间不可修改。仅在开发时设置 `DOCLIGHT_DEV_MODE=true`，登录后内置空间显示完整的空间页和管理入口，可以修改空间名称、描述、排序与 slug，新建、编辑、重命名、移动或递归删除页面，也可以删除整个内置空间。这些操作直接修改应用的 `template/` 源码，不会写入用户数据目录。

重命名空间 slug 后，旧的空间链接和 Markdown 中硬编码的旧空间链接不会自动更新。

一次结构修改可能涉及多个模板文件，因此会先在安装目录的 `.doclight/` 写入事务日志，再逐文件替换；进程中断后会在下次启动或下一次结构修改时自动补完。运行期间不要用其他程序并发修改模板，也不要让多个 DocLight 进程使用不同的安装目录；该机制面向本机单实例开发，不支持 NFS 或多主机挂载。

此模式允许服务器按正常配置监听公网，**不要在生产环境启用**；需要写入模板目录的文件权限，源码更改应自行检查后再发布。

### 备案号悬挂

面向中国大陆服务器的合规要求：备案号需悬挂在页面底部并链接至主管机关查询系统。
配置后效果如下（未配置则整块不存在）：

```toml
# doclight.toml
icp = "浙ICP备12345678号-1"
police = "京公网安备11010502030123号"
copyright = "© 2026 Mooling"
```

实现上有三点是刻意为之：

- **服务端注入，而非前端渲染**。合规检查抓取的是原始 HTML，不执行 JavaScript；
  若把备案号交给 SPA 生成，人工访问看着正常，机器核查却是空页。因此页脚由
  `src/beian.ts` 在服务端渲染并写入 `public/index.html` 的注入标记位，
  `curl` 直接就能看到。
- **Nix 模块把备案信息写进生成的 TOML，不再走环境变量**。这从根本上绕开了 systemd
  对 `Environment` 的字符串解析：含空格的值（如 `© 2026 Mooling`）不再有被截断的风险，
  服务只通过 `DOCLIGHT_CONFIG` 拿到文件路径。
- 若仍需环境变量传递，注意**不能写进 systemd 的 `Environment` 列表**：列表元素是裸字符串，
  nixpkgs 不加引号，`© 2026 Mooling` 会被 systemd 解析成第二个赋值而截断成 `©`。

| --- | --- |
| 可视化编辑 | H1–H3、粗斜下删、行内代码 / 代码块、列表、引用、链接、图片、分隔线；撤销重做、快捷键（⌘S/B/I/U/Z）、Tab 缩进 |

| Markdown 源码编辑 | 编辑器顶部「可视化 / Markdown」切换：直接编辑源码，两模式**不丢编辑内容**（切换即序列化 / 渲染；源码经可视化回存会被规范化） |

| 空间管理 | 新建 / 重命名 / 编辑路径 / 删除（含空间内全部页面）；锁定后禁止修改，解锁须验证站长登录密码；可开启「自动按顺序推荐其他文章」，在文章底部显示上一篇 / 下一篇卡片 |

| 阅读体验 | 正文默认限宽，桌面端可拖拽把手调整宽度（双击复位、本地记忆，自动限制在可视区域内） |

| 工程细节 | TypeScript 编译、SPA 回退路由、原子化 JSON 写入、请求日志、移动端抽屉导航、打印样式 |

### 内容格式与迁移

页面正文以 **Markdown** 存储，且**每页一个真实 `.md` 文件**：

```
data/pages/welcome.md
---
title: 欢迎使用 DocLight
space: default
parent: null
createdAt: 1787769399200
updatedAt: 1787769399200
---

# 欢迎使用 DocLight ✦
…正文…
```

这样可以直接导出、放进 Git 管理，或用任意编辑器**离线修改**——服务端每次读取都从磁盘
重建，改动无需重启即可生效。front matter 缺失时会从容错处理：标题从首个 `#` 标题推断、
时间取文件时间；未知键忽略；指向已删除空间的页面回退到第一个空间而不是消失。

Markdown 无法表达的格式（下划线 `<u>`、对齐 / 颜色等内联样式）会**原样保留为内联 HTML**；
渲染时先经 `marked` 解析、再由 DOMPurify 净化后插入 DOM，内联 HTML 因此不会成为 XSS 入口。

**旧数据自动迁移**：若数据目录里存在旧版单文件 `data/pages.json`（`version: 3` 的 HTML
或 `version: 4` 的 Markdown 字符串），首次启动会将其拆分并写入上述文件布局，原文件移作
`pages.json.bak` 以便回退，内容不会丢失。`pages/` 里已有的手写页面不受迁移影响；若旧文件
**无法解析**，也会先按 `pages/` 里既有的页面恢复索引；若没有页面可恢复，则初始化空的用户数据目录。

迁移完成后原文件会被**移走**（而非留在原地），否则一旦 `spaces.json` 丢失，那份过期快照
会被当作"待迁移数据"重新导入、覆盖你后来的编辑。若 `pages.json` 与既有 `.bak` **内容不同**
（如同一份快照从别的机器拷来），会另存为 `pages.json.bak.N` 而不是被丢弃。

**迁移必须只发生一次**：迁移会在数据目录写下 `pages.json.migrated` 作为完成标记（**故意不是
隐藏文件**，否则常被同步工具默认排除，反而丢失这条判据）。之后即便旧文件因崩溃窗口、retire
失败或被拷回而再次出现，也一律视为残留而不再迁移。仅凭"没有 `.bak`"无法区分首次迁移与残留：
曾因此把用户**已删除**的页面重新建了出来——`onlyCreate` 只保护"已存在"的文件，而"文件不存在"
既可能是快照该补的，也可能是用户刚删掉的。

> 若你要**主动**把一份旧导出重新导进来：把 `pages.json` 放进数据目录后，**先删掉
> `pages.json.migrated`、`pages.json.bak` 与 `spaces.json`** 再启动（三个都要删：标记和备份会让
> 它被判为残留，而留存索引会走"store 已存在"分支直接把它移走）。迁移只会**补建**缺失的页面，
> 不会覆盖你现有的 `.md`。

**迁移不得覆盖比它更新的东西**：迁移只会**新建**缺失的页面文件（`onlyCreate`），
已存在的 `.md` 与已存在的 `spaces.json` 都视为用户的最新数据而保留——回灌一份旧快照即使
发生（如迁移写入后进程崩溃、文件又被拷回），也只会补上缺失的页面，不会回退你的编辑。空间
索引同样按此规则保护：空间名与描述**只**记录在 `spaces.json` 里，若允许旧快照覆盖它，重命名
过的空间会被改回、快照之后新建的空间会连同其页面归属一起消失。迁移时因此会把快照的空间
列表与磁盘页面所呈现的空间**合并**（同名以快照为准，磁盘独有的补入）。

**删改只针对明确操作**：只有通过界面删除 / 重命名的页面才会移除对应文件——写入时不会
"清理所有未出现在内存里的文件"，因此读取失败的文件或手工放进去的页面都不会被误删。

**页面顺序由数据决定，而非目录顺序**：侧栏与空间索引页的页面顺序取自空间自己的排序设置（默认按 `createdAt` 降序，即最新创建在前），**不是** `readdirSync` 的返回顺序——目录序只在小容量 ext4 目录上才近似创建序，换到 APFS / NTFS 或目录增大（htree）后会变成哈希序，侧栏可能毫无征兆地重排。每个空间各自选择排序方式，取值记在 `spaces.json` 空间记录的 `sort` 字段里：`created_desc`（最新创建在前）、`created_asc`（最早创建在前）、`updated_desc`（最近编辑在前）、`updated_asc`（最久未编辑在前）、`title_asc`（标题顺序，按中文排序规则比较）与 `manual`（手动排序）。选择默认项时会**清除**该字段而非写入当前默认值，这样将来调整默认值仍能作用到没设过的空间。时间戳相同时以 slug 兜底，保证顺序是确定的；手工把 `sort` 改成非法值会在读取时被忽略并回落到默认排序。

**手动排序**（`sort: "manual"`）另用一个 `order` 数组记录页面顺序，元素是本空间页面的 slug，按阅读顺序给出（含子页面的完整深度优先序列）。`order` **只在**该空间的 `sort` 为 `manual` 时生效，写在别的排序模式下不产生任何效果；非字符串、不合法 slug 与重复的条目在读取时即被丢弃，不是数组或过滤后为空则整个 `order` 键被删除。切到手动排序时若请求没带 `order`、该空间也还没有 `order`，服务端会按**切换前**的排序结果种下一份顺序，所以第一次拖动是从现状微调而不是从随机顺序开始。`order` 里没列到的页面（排序之后新建的）排在已列出页面之后，并保持各自的相对次序。页面重命名时 `order` 中的旧 slug 会**原地替换**为新 slug（保留它被拖到的位置）；页面被删除或移动到其他空间时对应条目会被移除——残留条目会让之后的重新提交被拒，也可能被日后的同名页面「继承」。

**推荐上一篇 / 下一篇**：空间记录的 `recommend` 只在开启时为 `true`，关闭即删除该键而**不写** `false`。开启后文章底部出现「← 上一篇」「下一篇 →」卡片，顺序由深度优先遍历该空间的页面树得到，并沿用该空间的排序键——子页面紧跟在父页面之后、父页面的下一个兄弟之前，而不是把所有嵌套页面甩到空间末尾。遍历不会进入同一个 slug 两次，手工编辑造成的环或悬空 `parent` 也不会让阅读入口失效；只有一页的空间不显示卡片，处于首尾时缺的那一侧自动省掉。

排序与推荐有三处入口，改的是同一份空间记录：**空间索引页**右上角的「排序」下拉与「启用推荐」开关、同一页的「空间设置」弹窗（内含相同的排序下拉与推荐开关），以及侧栏空间行「⋯」菜单里的**「空间设置…」**。最后这条是必需的——空间若设了首页（如示例空间的 `home: welcome`），访问 `/空间slug` 会直接打开首页而**不会**显示空间索引页，只靠索引页的话这类空间将永远无法修改排序。无论从哪进，都只提交**改动过**的字段，选默认排序时提交 `null`（等价于删除该键），因此单纯拨动推荐开关不会顺手把排序键写实。

注意区分两个页面：**空间总览**（`/` 或 `/spaces`，页面标题「空间」）列出**全部**空间，只提供「＋ 新建空间」入口，本身不参与页面排序；**空间索引页**（`/<空间slug>`）只显示**单个**空间的顶层页面卡片，排序下拉、推荐开关与手动拖动都在这里。手动拖动的两个入口同属「手动排序」：空间索引页的卡片可用鼠标在任意位置拖起（触屏与手写笔从卡片右上角的握把起拖），侧栏则从行左侧的握把拖动同级页面；两者都只在落点与当前位置不同时才提交，并会自动把该空间切到手动排序。

通过空间索引页的「空间设置」按钮或侧栏空间行「⋯」菜单中的「空间设置…」，可以锁定或解锁普通空间：锁定后仍可公开阅读，但空间及其页面不能通过 API 修改或删除（返回 423）。**解锁必须再次验证站长登录密码**，而验证过程里密码**不会被发送**——浏览器先用 `GET /api/auth/challenge` 取到一次性 `nonce`，在本地重新派生密钥并算出 `HMAC-SHA256(密钥, nonce)`，只把这个 `proof` 连同 `nonce` 提交给 `POST /api/spaces/:slug/lock`；服务端用同样的一次性 nonce 复算并做定长时间比较，随后立即作废该 nonce 以防重放。解锁同时要求有效的登录会话，但**不需要**用户名（会话已确定身份）；连续失败同样受每 IP 8 次 / 120 秒的限流约束，错误信息与登录一致（`用户名或密码错误`），不区分是密码错还是账号错。锁定状态存放在数据目录的 `spaces.json` 中（只在锁定状态下写入 `locked: true`，解锁即删除该键），请与页面文件一同备份；若索引丢失并从页面重建，普通空间的锁定状态无法恢复。内置 `doclight-default` 的只读保护由程序强制实施，不依赖数据目录中的锁定状态，管理员也不能通过 API 解锁或修改（`PUT` 与锁接口都会返回 `423`，后者即使在开发者模式下也不例外）；内置内容以随应用发布的 `template/` 为准，仅在 `DOCLIGHT_DEV_MODE` 下才允许已登录用户改写模板源码（此时修改走的是模板分支，同样写入 `template/` 而非数据目录）。锁定是防误修改功能，不加密文件，也不能阻止直接访问服务器文件的人员修改数据或应用源码；同一数据目录应只由一个 DocLight 服务进程写入。密码验证不替代传输加密，远程访问应使用 HTTPS。

页面的新建 / 重命名 / 改 slug / 移动 / 保存成功后会重新拉取一次 tree，而不是仅改内存数组：
顺序由服务端按上面的规则计算，本地增删无法复现，只改内存会让侧栏保持旧顺序直到刷新。

**空间索引可自愈**：空间索引是派生数据（每个页面的所属空间都记在它自己的 front
matter 里），若该文件被误删、同步不全、内容为空或损坏，下次启动会依据 `pages/` 里既有的
页面重建索引，**不改动任何页面文件**——而不是用示例数据覆盖同名页面。**服务运行期间**同样
生效：索引若在运行中被清空，下一次请求即会按页面重建，不会把页面折叠到兜底空间并在随后的
保存中把这种错误归属写回磁盘。若站点确实已被清空（没有任何页面），则视为正常状态而不填充
示例数据；但此时**若还留着旧版单文件**，那它就是这份站点的唯一数据，会被迁移进来而不是被
移走。

注意重建只能还原每个页面**属于哪个空间**（front matter 里有记录），空间自身的**标题与描述**
只存在于 `spaces.json`，索引一旦丢失便无从恢复，会退化为以空间 slug 作标题。页面内容与归属
不受影响。

### 可视化 / Markdown 双模式

编辑页顶部可在两种模式间切换，二者描述**同一份 Markdown 文档**：

- **可视化**：所见即所得（`contenteditable`），保存时把 DOM 序列化为 Markdown；
- **Markdown**：直接编辑源码（`textarea`），保存时原样提交。

切换**不丢编辑内容**：离开可视化前先序列化，进入可视化时再渲染，因此当前编辑内容不会
因切换而丢失；源码模式还支持 `Tab` / `Shift+Tab` 缩进。Markdown 模式下格式化工具栏自动
隐藏——那些按钮基于 `execCommand`，只对可视化 DOM 有意义。

> 注意：源码**经可视化模式下再保存**时会被规范化——`__粗__` → `**粗**`、`* 项` → `- 项`、
> `1)` → `1.`、Setext 标题 → ATX、多余空行合并，HTML 注释（`<!-- … -->`）会被丢弃。
> 语义不变，但源码字节会变；想保持源码原样就不要在其间切到可视化模式。

## 账号与登录

本站只有**一个**站长账号，没有注册、多用户或权限分级。首次运行时右上角显示「初始化账号」，点开设置用户名与密码即完成初始化；初始化成功后会自动登录并发出会话 cookie，按钮变成「退出」。文章阅读页也提供账号入口，进入编辑状态后暂时隐藏。此后 `data/auth.json` 已存在账号，再次调用初始化接口会被拒绝（`403 账号已初始化，请直接登录`）。

**校验规则**（在浏览器里拦截，格式不符不会发出请求）：

- 用户名：`/^[A-Za-z0-9_-]{1,40}$/`，只能是字母、数字、下划线、连字符，1–40 位；服务端在 `setup` 时用同一条规则复核；
- 密码：`/^[\x20-\x7E]+$/` 且长度 ≥ 6，即只能是可打印 ASCII（英文、数字与半角符号），不能含中文或全角字符——空格是被允许的字符。服务端看不到密码，无从校验，这条规则只在前端生效；
- 初始化时两次输入须一致；密码没有长度上限，也没有复杂度强制。

**密码不会以明文离开浏览器，也不落盘**。初始化时浏览器用 PBKDF2-SHA256（10 万次迭代，16 字节随机盐）把密码派生为 32 字节密钥 `ks`，只提交 `ks`；服务端 `data/auth.json`（权限 `0600`）里存的是 `user`、`salt`、`iters` 与 `stored`（即 `ks`），**没有**密码本身的任何形式。此后 `ks` 也不再上网：登录时先用 `GET /api/auth/challenge` 取回 `nonce`（16 字节随机值，60 秒有效，用后即废），浏览器用密码**在本地**重新派生出 `ks`，算出 `HMAC-SHA256(ks, nonce)` 作为 `proof` 提交；服务端用存下的 `ks` 复算并做**定长时间**比较——窃听者拿到的 `proof` 对下一个 nonce 无效，无法重放。比较时用户名与口令两条分支都会被算完，不因先失败而短路；两者错误统一返回 `401 用户名或密码错误`，不泄露是哪一项不对。每个 IP 连续失败 8 次后限制 120 秒（`429 尝试过于频繁，请两分钟后再试`），成功后计数清零。

浏览器没有 WebCrypto 的 `crypto.subtle` 时（典型情形是在**非 localhost 的 http 源**上，该 API 属于安全上下文），前端会回退到内置的纯 JS 实现，功能一致但明显更慢；控件在此期间显示「验证中…」并禁用，避免重复提交。

**匿名访问拿不到用户名**：`GET /api/auth/state` 对未登录的访客返回 `user: null`，`GET /api/auth/challenge` 更是只给 `nonce` / `salt` / `iters`——两处都不返回账号名（减少未认证访问者获取账号名的机会）。因此登录框的**用户名由浏览器本地记住**（`localStorage` 键 `doclight-login-user`，只存名字，浏览器禁用存储时静默跳过而不影响登录），应用不会将密码、派生密钥、nonce 或 proof 写入本地存储；是否由浏览器密码管理器保存密码取决于用户和浏览器设置。换浏览器或清过站点数据后需要重新输入用户名，这属于预期行为。

会话是 `HttpOnly; SameSite=Strict` 的 `dl_sess` cookie（`Path` 取部署前缀，`Max-Age` 7 天），服务端在内存里**滑动续期**——每次带会话的请求都会把过期时间重推到 7 天后。会话只存在内存中，**重启服务即全部失效**，需要重新登录；`auth.json` 里的账号本身不受影响。

> ⚠️ **协议本身不提供传输加密**：cookie 也没有 `Secure` 标记，服务端不做 TLS。上面这些措施防的是「密码明文被记录」「凭据被重放」「匿名者探测账号名」，**不能**替代 HTTPS——明文 http 下链路上的 `ks`、`proof` 与服务端下发的会话 cookie 仍可被抓取并直接冒用。远程访问务必用反向代理套 TLS（或走内网 / Tailscale 之类的加密隧道），仅供本机访问时也应确保服务没有意外暴露到网络。

忘记密码时没有自动找回流程。重置前应先停止服务、限制网络访问并备份数据目录；移除认证记录后，服务会回到未初始化状态，必须在仅受信任人员可访问的环境中立即重新初始化账号，否则他人可能抢先设号。已有会话保存在内存中，停止并重启服务才会清除它们；页面和空间数据应单独保留。

## Nix / NixOS

仓库自带 `flake.nix`（已启用 flakes），无需本机安装 Node 或 npm：

```bash
# 直接运行，数据写入 ${XDG_DATA_HOME:-~/.local/share}/doclight
nix run .

# 换个起始端口 / 指定数据目录（环境变量覆盖配置）
PORT=8080 nix run .
DOCLIGHT_DATA_DIR=/tmp/docs nix run .

# 用配置文件（此时由文件里的 dataDir 决定数据位置，包装器不再注入）
DOCLIGHT_CONFIG=/path/to/doclight.toml nix run .

# 构建到 ./result（命令名 doclight）
nix build .#default
./result/bin/doclight

# 开发环境（nodejs_22 / typescript-language-server / nixfmt）
nix develop

# 跑回归测试（复用包定义，在构建目录里执行 npm test）
nix flake check
```

`nix run .` 会在源码变化时重新编译；注意 flake 取的是 **Git 树**，新增文件需要先 `git add`（不必 commit）。

> 首启自动生成模板只在项目根可写时发生；`nix run` 下项目根位于只读的 store，因此**不会**也无法生成文件，
> 想要配置文件请照上面的例子用 `DOCLIGHT_CONFIG` 指定（或直接用 NixOS 模块的 `settings`）。

> 用 `DOCLIGHT_CONFIG` 指定配置文件时，包装器**不再**注入 `DOCLIGHT_DATA_DIR`，因为环境变量优先级高于文件，
> 那会静默压掉文件里的 `dataDir`。因此这种情况下请在配置文件里写 `dataDir`（或另外显式设 `DOCLIGHT_DATA_DIR`）：
> 否则默认数据目录会落在只读的 Nix store 下而无法写入。

NixOS 上也可以声明式部署：

```nix
{
  inputs.doclight.url = "github:Mooling0602/DocLight";

  # 在 NixOS 配置里
  imports = [ inputs.doclight.nixosModules.default ];

  services.doclight = {
    enable = true;
    port = 4173;
    address = "127.0.0.1"; # 默认只监听回环，公网经反向代理
    openFirewall = false;

    # 备案信息（面向大陆服务器）；不填则页面底部不出现该区块
    icp = "浙ICP备12345678号-1";
    police = "京公网安备11010502030123号";
    copyright = "© 2026 Mooling";

    # 逃生口：直接写入生成 TOML 的任意配置项（细粒度选项优先级更高）
    settings = {
      host = "127.0.0.1";
    };
  };
}
```

模块把上述选项生成一份 TOML 交给服务，只通过 `DOCLIGHT_CONFIG` 传路径——备案信息不再走
环境变量，因此 `© 2026 Mooling` 这类含空格的值不会再被 systemd 截断。

服务以 `DynamicUser` 运行，数据落在 `/var/lib/doclight`（systemd `StateDirectory`）。
配置了 `address = "0.0.0.0"` 时才需要 `openFirewall = true`。

> **为什么数据目录必须外置**：包安装到只读的 Nix store，而 DocLight 会写 `pages/*.md`、
> `spaces.json` 和 `auth.json`。模块把 `dataDir` 写进生成的 TOML 并同时设置 `DOCLIGHT_DATA_DIR` 对齐
> systemd 状态目录；`strictPort = true` 也由模块固定注入，端口占用直接失败——否则自动
> 探测会静默漂到下一个端口，反向代理就落空了。
>
> 合并顺序为 `模块默认值 < settings < 细粒度选项`，模块强制项（`strictPort`、`dataDir`）
> 最后注入、不可覆盖。注意 `port` / `address` 的默认值是 `null`（而非具体值），这样
> `settings.port` 才能生效；真正默认值在合并后补上。

## REST API

```
GET    /api/tree                    空间和页面元信息树（页面不含 content）
GET    /api/pages                   页面元信息列表（不含 content）
GET    /api/pages/:slug             单页详情（含 content）
POST   /api/pages                   新建 {title, space, parent?}
PUT    /api/pages/:slug             更新 {title?, content?, slug?, space?, parent?}
DELETE /api/pages/:slug             删除页面及其子页面

POST   /api/spaces                  新建 {title, desc?}
PUT    /api/spaces/:slug            更新 {title?, desc?, slug?, sort?, recommend?, order?}
DELETE /api/spaces/:slug            删除空间及其页面
POST   /api/spaces/:slug/lock       锁定 / 解锁 {locked}
                                    解锁另需 {locked:false, nonce, proof}

GET    /api/auth/state              登录状态 {mode, authed, user, salt, iters}
GET    /api/auth/challenge          登录挑战 {nonce, salt, iters}（60 秒有效、一次性）
POST   /api/auth/setup              初始化账号 {user, ks}
POST   /api/auth/login              登录 {user, nonce, proof}
POST   /api/auth/logout             退出（清除会话 cookie）
```

写操作（`POST` / `PUT` / `DELETE`，`/api/auth/*` 除外）都需要有效会话，否则返回 `401 {error, needAuth: true}`；读取始终公开。请求体会在鉴权后重新校验一次会话，因此慢速上传途中被吊销的会话不会漏过。

`PUT /api/spaces/:slug` 的字段都是可选的，语义如下：

| 字段 | 说明 |
| --- | --- |
| `title` | 去除首尾空白、超长则截断到 120 字符；结果为空返回 `400` |
| `desc` | 去除首尾空白、超长则截断到 200 字符；可为空串 |
| `slug` | `^[a-z0-9_]{1,80}$`，`spaces` 与 `api` 为保留字，与已有空间 / 页面撞名返回 `400 该 slug 已被占用`；界面总是**单独**提交它（改名要连带改写该空间下所有页面的 `space`，混在别的修改里无法优雅回滚） |
| `sort` | `created_desc` / `created_asc` / `updated_desc` / `updated_asc` / `title_asc` / `manual`；传 `null` 清除并回到默认 |
| `recommend` | 布尔；`false` 记为清除该键而非写入 `false` |
| `order` | 页面 slug 数组，元素必须属于本空间（否则 `400 order 只能包含本空间内页面的 slug`）且不重复（否则 `400 order 中不能出现重复的 slug`），空数组等于清除；只有 `sort: "manual"` 时才影响实际顺序 |

（普通空间对 `title` / `desc` 的超长是**截断**而非报错，只有 `title` 截断后为空才返回 `400 空间名称不能为空`；内置空间在开发者模式下走另一条分支，超长直接拒绝并回 `400 空间名称须为 1–120 个字符`，且**该分支要求 `slug` 必须单独提交**，混发返回 `400 空间 slug 无效或不能与其他修改同时提交`。）

`/api/spaces/:slug/lock` 对内置空间**总是**返回 `423`（没有开发者模式例外），普通空间的解锁参数见上文「账号与登录」：`proof = HMAC-SHA256(ks, nonce)`，`ks` 为浏览器用密码派生的密钥；**任何接口都不接受明文密码**。错误响应统一是 `{error: "说明"}`（业务错误为中文，报文级的 `413` / `400` 除外，其消息为 `body too large` / `invalid JSON`）。常见状态码：`400`（参数非法、挑战过期或 slug 冲突）/ `401`（未登录或凭据错误）/ `403`（账号已初始化）/ `404`（对象不存在）/ `409`（内置空间在开发者模式下改 slug 撞名、模板路径重叠，或页面改名竞态后要求刷新重试）/ `413`（请求体超过 1 MiB）/ `423`（空间已锁定，或内置空间不允许该操作）/ `429`（尝试过于频繁）/ `500`（鉴权记录损坏时为 `鉴权记录损坏，请重新初始化`，其余未预期异常一律替换为 `服务器内部错误` 以免泄露文件系统路径）/ `503`（数据目录里已有与内置空间保留 slug 冲突的实体，响应额外带 `errorCode: "BUILT_IN_SLUG_CONFLICT"`，此消息可安全展示）。

> 页面和空间的写操作需要登录。定位：个人 / 小团队本地知识库；多用户权限、协同编辑不在范围内。
